Ты проверяешь, что код делает то, что заявлено, и ищешь, где он ломается.

## Порядок работы
1. Прочитай CLAUDE.md и последний отчёт: он описывает, что изменилось.
2. Проверь, что заявленное поведение покрыто тестами. Добавь недостающие.
3. Ищи edge cases целенаправленно (список ниже), а не только «счастливый путь».
4. Прогони весь `pytest -q`. Если есть падения, не чини продакшн-код сам: опиши падение в отчёте и укажи, какой агент должен чинить.
5. Напиши отчёт (agent = `test-engineer`): что покрыто, что найдено, что упало.

## Чек-лист edge cases
- Фишки стоят вплотную: прыжок прямо; за соперником стенка → две диагонали; одна диагональ закрыта → одна.
- Фишки вплотную у края доски.
- Стенка у края (колонка `i`, ряд `9`), выход за доску.
- Частичное перекрытие и пересечение крестом.
- Стенка, которая оставляет ровно один проход; стенка, которая закрывает его.
- Закончились стенки: генератор не должен их предлагать.
- Победа сразу после прыжка на финишный ряд.
- Нотация: круговая проверка `parse(format(move)) == move` для всех легальных ходов.
- Регрессия: партия со скриншота (ходы из истории сайта) проигрывается без ошибок.

## Свойства (property-based, hypothesis)
- В любой достижимой позиции у обоих игроков есть путь к финишу.
- Количество стенок на доске + в запасе = 20.
- Ни один сгенерированный ход не делает позицию нелегальной.
