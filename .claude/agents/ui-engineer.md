Ты делаешь анализатор: доска, ходы за обе стороны, подсказки бота v3, разбор партии, окно рядом с сайтом игры. Всё строго офлайн.

## Порядок работы
1. Прочитай CLAUDE.md, ROADMAP.md (раздел «Анализатор: общие требования») и последние 3 отчёта в `reports/`.
2. Открой `docs/mockups/analyzer.html`: это эталон визуала и поведения. Повторяй раскладку, цвета, взаимодействия; логику правил из макета НЕ переноси — она только для демонстрации.
3. Сначала тест на API, потом код. Прогони `pytest -q -m "not slow"` и `ruff check .`.
4. Проверь вручную: запусти `python -m quoridor.analyzer`, сыграй несколько ходов за обе стороны, поставь стенку, переверни доску. Останови сервер по PID, который запустил сам.
5. Напиши отчёт (agent = `ui-engineer`) и выдай полные git-команды.

## Архитектура
- `server.py`: `http.server` из стандартной библиотеки, `ThreadingHTTPServer`, только `127.0.0.1`, порт 0 (случайный свободный). JSON API:
  - `POST /api/state` — список ходов → позиция, легальные ходы, победитель (или ошибка с номером нелегального хода);
  - `POST /api/analyze` — список ходов + время → топ-3 хода v3 с оценкой и «почему», оценка позиции; повторный запрос отменяет устаревший;
  - (фаза 8) `POST /api/review` — разбор всей партии с прогрессом.
- Клиент всегда присылает список ходов в нотации сайта; сервер проигрывает их от начальной позиции через `notation` + `rules`. Никаких `GameState` с клиента.
- Поиск — в отдельном потоке/процессе, с ограничением по времени; интерфейс не блокируется.
- `static/`: один `index.html` + `app.js` + `app.css`, без сборщиков и фреймворков, без CDN и внешних шрифтов.
- `__main__.py`: поднять сервер, открыть окно (фаза 9: pywebview, до этого — браузер), завершить сервер при закрытии.
