## Что сделано
- `engine.py`:
  - `parse_game_text(text)`: токены через пробелы / переводы строк / `,` / `;`, всё после `#` отбрасывается, ведущий номер `12.` снимается, регистр не важен; каждый токен нормализуется через `notation`, весь список проигрывается `replay` (ошибка с номером хода). Формат файлов `game0N.txt` («белый чёрный» в строке) принимается как частный случай. Лимит `MAX_MOVES`.
  - `review_game(moves, seconds, cancelled)`: генератор, один шаг на позицию 0..N (последняя позиция без хода). На позицию: `rank_moves` (топ-3, `search_top`) + оценка сыгранного хода. Если сыгранный ход в топе с точной оценкой, берётся она; иначе `_score_move` (`search_root(moves=[mv])`, то же, что `evaluate_move` из 0053). Бюджет: `time` на позицию; 60% на топ и 40% на отдельный поиск сыгранного хода (40% не тратятся, если ход в топе). Терминальная позиция: мгновенно, оценка мат.
  - `mark_for`, `move_accuracy`, `summarize`; `evaluate_move` и `analyze` рефакторены на общие `_score_move` и `_top_entries` (поведение прежнее).
- `server.py` (только `127.0.0.1`, как и раньше):
  - `POST /api/parse {text}` -> `{moves}`; ошибки 400 с `bad_move`.
  - `POST /api/review {moves, time}` -> `{id, total}`: фоновый поток `ReviewJob`; новый разбор отменяет предыдущий и текущую подсказку; пустой список, нелегальный ход, нечисловой `time` -> 400. `time` по умолчанию 1.0 с, зажимается в 0.1..10 с.
  - `POST /api/review/status {id, since}` -> `{done, total, finished, cancelled, error, results[since:], summary}`: опрос; чужой id -> 404; `since` не целое/отрицательное -> 400.
  - `POST /api/review/cancel {}`. `server_close()` отменяет разбор.
  - Клиент по-прежнему шлёт только списки ходов; `GameState` с клиента не принимается.
- Клиент (`index.html`, `app.js`, `app.css`; без inline-скриптов и стилей в разметке, без внешних ресурсов):
  - `line` теперь вся партия, `ply` текущая позиция; на сервер уходит `line.slice(0, ply)`.
  - Листание: кнопки « ‹ › », клавиши ← → Home End, клик по ходу в списке, клик по графику. Backspace и буквенные клавиши не срабатывают в поле ввода и textarea.
  - Загрузка: textarea + «Загрузить и разобрать» (парсинг на сервере, сразу запускает разбор) и отдельная «Разобрать партию» (текущий список, в т.ч. после правок). Поле «Бюджет, с/позицию». Во время разбора кнопка превращается в «Остановить разбор». Прогресс: `<progress>` и «Разбор: N из M позиций». Опрос раз в 0.35 с, UI не блокируется.
  - Пометки `?? ? ?! !` рядом с ходами (подсказка «потеря X шага»), строка под списком «Ход X ?: потеря 1.8 шага, лучше было Y», график оценки (кружки на ?? и ?, курсор на текущей позиции, клик), сводка по сторонам (точность, число пометок).
  - Подсказки (H): пока идёт разбор, отдельный анализ не запускается (не отнимаем CPU); для позиций, которые разбор уже посчитал, показывается его топ-3 («Из разбора: глубина…»); после окончания остальные позиции считаются как раньше.
  - Ветки: ход, отличный от `line[ply]`, отрезает хвост, исходная партия запоминается (`mainLine`), ходы ветки синие; такой же ход, как в партии, просто листает вперёд. «Отменить» на загруженной партии (или в середине списка) тоже создаёт ветку; «Вернуть партию» возвращает исходный список. Пометки разбора остаются у общего начала ветки и партии.
  - «Копировать ходы» копирует всю `line` (если буфер недоступен, ходы кладутся в поле загрузки).

## Пороги разметки и формула точности
Потеря хода (loss) = лучшая оценка позиции для ходящего минус оценка сыгранного хода, в сотых шага (display_score). Каждая оценка зажимается в ±10 шагов, доказанный выигрыш/проигрыш считается как ±12 шагов (чтобы пропуск форсированного выигрыша или ход в форсированный проигрыш были грубой ошибкой даже из уже проигранной позиции). loss не меньше 0; если сыгран ход №1 бота, loss = 0.

| Метка | Условие |
|---|---|
| `??` грубая | loss ≥ 3.0 шага |
| `?` ошибка | loss ≥ 1.5 |
| `?!` неточность | loss ≥ 0.75 |
| `!` | сыгран лучший ход, а второй ход хуже на ≥ 1.5 шага (оценка второго бывает верхней границей, тогда реальный разрыв не меньше) |

Точность хода = max(0, 100 − 25 · loss в шагах) = `100 − loss/4`. Точность игрока = среднее по его ходам. Пороги и вес 25 взяты из макета (шкала макета в шагах, у v3 тоже шаги). Все константы в `engine.py` (`MARK_*`, `REVIEW_*`, `PLAYED_SHARE`); считает сервер, клиент только показывает.

## Решения и почему
- Опрос вместо потока чанков: проще на `http.server`, нагрузка мала.
- Разбор не делит процессор с подсказками: клиент не запускает анализ, пока разбор идёт; на сервере новый разбор отменяет текущую подсказку, но не наоборот.
- Парсинг текста на сервере: знание о нотации остаётся в одном месте.
- Точность и пометки считает сервер.
