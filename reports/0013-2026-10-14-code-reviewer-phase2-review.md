## Что сделано (проверено)
- **Корректность ботов.** `RandomBot` выбирает из `legal_moves`. `GreedyBot`: выигрывающий шаг берётся сразу; стенка только при строго лучшем счёте. Все ходы ботов проходят `is_legal_move` в тестах (позиции из случайных партий и полные партии с инвариантом 20 стенок).
- **Полнота кандидатов-стенок.** Аргумент из 0010 верен: стенка, удлиняющая путь соперника, должна перекрывать ребро каждого его кратчайшего пути, а значит и пути, найденного BFS. BFS игнорирует фишки, поэтому стенка вне кандидатов даёт счёт не выше базового, а лучший шаг фишкой даёт базовый +1. Сужение не теряет ни одного хода, который выбрал бы полный перебор. Дополнительно прогнал свою проверку на 1175 позициях из 30 случайных партий: множество удлиняющих стенок из `wall_moves` всегда входит в `candidate_walls`, расхождений 0; `len(shortest_path) - 1 == shortest_path_length` на всех; `pawn_moves` нигде не пуст.
- **`paths.shortest_path`.** BFS с `parent`-словарём, детерминированный порядок `DIRS`, без I/O и глобального состояния. Длина согласована с `shortest_path_length`.
- **Чистота rules/paths.** grep по `rules.py`, `paths.py`, `state.py`, `bots.py`: нет `print`/`input`/`open`/`global`/модульного `random`. У ботов свой `random.Random(seed)`.
- **Офлайн.** Импорты в `quoridor/` только stdlib и свои модули; сетевых библиотек нет.
- **Нотация.** Ввод и вывод ходов в CLI только через `parse_move`/`format_move`. Тесты больше не используют `ord`/`chr` (0009). Остаток: подписи осей в `render` (см. minor 1).
- **Отрисовка и `blocked`.** `|` и `---` строятся из `GameState.blocked`; стык берётся из `h_walls`/`v_walls` по внутреннему якорю `(col, row-1)`, это и есть центр стенки. Проверил вручную: `e5h` рисуется между рядами 5 и 4 на колонках e-f, `a4h` между 4 и 3 на a-b, что совпадает с правилом нотации из CLAUDE.md.
- **Ввод CLI.** `strip().lower()`, мусор и Unicode отклоняются, нелегальный ход даёт повтор запроса, EOF = quit, после конца партии ввод не читается.
- **Отчёты 0009-0012.** Все по шаблону, номера идут подряд. Git-секции перечисляют файлы явно, без `git add .`; все изменённые и новые файлы из `git status` покрыты. Порядок коммитов 0009 → 0010 → 0011 → 0012 собирается без поломок.
