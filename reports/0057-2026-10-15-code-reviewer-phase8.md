## Что проверено
- **Правила не тронуты.** `rules.py`, `paths.py`, `notation.py`, `eval.py`, `bots.py` не изменены (`git diff --stat` пуст). I/O и глобального состояния в них не появилось.
- **Нотация.** Вне `notation.py` новых знаний о формате нет: `parse_game_text` только режет текст на токены (пробелы, `,`, `;`, `#`, номера `12.`), каждый токен проходит через `parse_move`/`format_move`. Клиент имена ходов не разбирает и не собирает: геометрия приходит с сервера.
- **v3 в SearchBot вне проигранных позиций не изменился.** Собственный A/B: `search.py` из HEAD против рабочей копии, v3-настройки (TT 18, вес 125), фиксированная глубина 3 и 4, 445 позиций из случайных партий (seed 100–114). Всего 890 поисков; 12 из них в доказанно проигранных позициях. В остальных 878 поисках ход, оценка, глубина и **число узлов** совпадают полностью: 0 расхождений. `_negamax` не менялся; в `_search` добавлены только запись `done_scores` (без копии) и кортеж `_root_info`. Горячий путь лишних аллокаций не получил.
- **search_root / search_top.** Окно multi-PV (alpha = k-я точная оценка) корректно; верхние границы для остальных ходов проверены тестом против plain negamax. В `search_top` лучший ход берётся из того же `_search`, что и у `search()`: ход, оценка и глубина совпадают (тест). Оценки альтернатив ограничены сверху лучшей оценкой и границей основного поиска. `_free()` в `finally`, таблицы между вызовами не держатся (тест).
- **Проигранная позиция.** `_lengthening_walls`: любая стенка, удлиняющая кратчайший путь, обязана перекрыть ребро каждого кратчайшего пути, поэтому достаточно рёбер одного пути. Легальность проверяется полностью: `wall_fits`, путь соперника не None, свой путь не None. Null-window проверка кандидатов корректна; mate-оценки с поправкой на ply сравниваются правильно.
- **display_score.** Только для показа; mate не меняется; для partial глубина +1. Влияния на поиск нет.
- **Офлайн / CSP / 127.0.0.1.** `HOST = "127.0.0.1"`, проверка Host/Origin, CSP `default-src 'self'` на всех ответах. В `index.html` нет inline-скриптов и inline-стилей. В `app.js` стили задаются через CSSOM (`.style.x`), под CSP это разрешено. `innerHTML` собирается только из строк сервера (имена ходов, `why`), ошибки показываются через `textContent`. Внешних URL нет (тест `test_static_dir_has_no_external_urls`). Google Fonts убраны из макета.
- **GameState с клиента не принимается.** Все маршруты (`state`, `analyze`, `evaluate`, `parse`, `review`) получают только списки ходов и проигрывают их через `replay` → `apply_move`. Тест `test_client_cannot_send_a_game_state`.
- **Потоки и отмена.** Анализ и evaluate занимают один слот `start_job`, новый запрос отменяет старый. Разбор (`ReviewJob`) — daemon-поток с `Event`, отмена проверяется в каждом листе (`_CancellableSearcher.evaluate`). Новый разбор отменяет старый и текущую подсказку, `server_close()` отменяет разбор. В памяти хранится один разбор. Ошибка внутри потока попадает в `error` и не роняет сервер. Неограниченно живущих потоков нет. Исключение — одна утечка CPU до 3 с, см. minor 2.
- **Валидация.** `time`: bool и нечисловые значения → 400; NaN/Infinity зажимаются в 0.1..10 через `_clamp_time`. `since`: целое ≥ 0. Чужой id → 404. Плохой evaluate/review не отменяет текущий расчёт (тесты).
- **Тесты на новое поведение.** search_root (против negamax, top-k, ход вне отбора, нелегальный ход), search_top == search, display_score, LOST и «не проигрывает быстрее», evaluate (+ ошибки, отмена), cancel, parse (разделители, комментарии, номера, ошибки с номером, лимит), пороги меток, точность, сводка, разбор (отмена, мат в финале, грубая ошибка), HTTP-маршруты разбора, сквозной тест в подпроцессе (остановка по своему PID), регрессия game02 (+ xfail на известное ограничение).
