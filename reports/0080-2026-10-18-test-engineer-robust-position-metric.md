## Задача
Фаза 9, шаг 2: метрика `tests/positions/score.py` зависела от времени, и одна чувствительная к нему позиция могла решить исход прогона. Нужна устойчивость: медиана по нескольким прогонам и/или фиксированный бюджет.

## Что сделано
- `--runs N` (по умолчанию 3, сид прогона i = i): итог это медиана доли верных позиций, рядом мин/макс. Так считаются все позиции, core и категории sign/move/shuffle.
- `--budget sims=N` (MCTS) или `--budget depth=D` (alpha-beta): фиксированная работа за ход, без часов. Результат детерминирован, поэтому с `--budget` `--runs` по умолчанию равен 1 (можно задать явно).
- Бюджет не того вида для бота (depth для MCTS, sims для alpha-beta) и кривой формат дают ошибку CLI. Боты без поиска (random, greedy) бюджет игнорируют.
- Для каждой позиции печатается доля прогонов, где она пройдена (`2/3 = 67%`), ходы по прогонам и пометка `<- unstable` для нестабильных. Итоговые строки: `median X% min Y% max Z%`, затем доли по каждому прогону.
- JSON при нескольких прогонах: `pass_rate`, `moves`, `all.{median,min,max,per_run}`, `budget`. Имя файла включает бюджет, например `v4-depth3.json`. Режим одного прогона без изменений.
- API: `Budget`, `parse_budget`, `make_scored_bot(..., seed, budget)`, `run_many`, `pass_rates`, `run_shares`, `median_min_max`, `report_runs`, `dump_runs`. Старые `run_all`/`report`/`dump` совместимы.

## Как запускать
```
python -m tests.positions.score --bot v4 --time 3                  # 3 прогона, медиана
python -m tests.positions.score --bot v4 --budget depth=4          # детерминированно, 1 прогон
python -m tests.positions.score --bot mcts --budget sims=400 --runs 2
# прочее: --only id,id  --procs N (<=4)  --out path  --no-dump
```

## Решения и почему
- Режимы независимы: время плюс медиана для проверки в боевых условиях, бюджет для воспроизводимых сравнений версий.
- Сид прогона i = i, а прогон 0 равен прежнему поведению (сид 0).
- Прогоны идут последовательно, внутри прогона `--procs`, чтобы держать нагрузку и шум по времени под контролем.

## Breaking changes
Нет. Вывод при `--runs 1` прежний. Поведение по умолчанию изменилось: теперь 3 прогона вместо одного, значит трёхкратное время. Для старого поведения используйте `--runs 1`.

## Проблемы и открытые вопросы
- Медленный тест `test_v4_handles_80_percent...` по-прежнему делает один прогон на 3 с. При желании перевести его на медиану из 3 или на `depth=`; решает ai-engineer.
- Бюджет depth не сопоставим по цене между v4 и v5 (разные ширины поиска). Для сравнения версий при равных ресурсах лучше время с медианой.
