## Задача
Фаза 2, шаг 1: `quoridor/bots.py` с протоколом бота, RandomBot и GreedyBot (только легальные ходы из rules).

## Что сделано
- `Bot` (Protocol): `choose_move(state) -> Move`.
- `RandomBot(seed)`: равномерный выбор среди `legal_moves`, свой `random.Random(seed)`.
- `GreedyBot(seed)`: максимизирует (путь соперника - свой путь) после хода. Выигрывающий шаг берётся сразу. Тай-брейк: шаг фишкой предпочтительнее стенки (стенка только при строго лучшем счёте), среди равных выбор через seed-RNG.
- Кандидаты-стенки (`candidate_walls`): только стенки, перекрывающие ребро текущего кратчайшего пути соперника. Это полный набор для цели «удлинить путь соперника» (любая удлиняющая стенка обязана перекрыть ребро любого кратчайшего пути), проверено тестом против полного перебора `wall_moves`.
- `paths.shortest_path(state, player)`: новая функция (BFS с восстановлением пути), нужна ботам.
- Нотация не затронута.

## Проверка
- Тесты: `pytest -q` -> 158 passed, 0 failed (бот-тесты ~5 с)
- Линт: `ruff check .` -> All checks passed; `ruff format .` без замечаний
- Тесты покрывают: легальность ходов на позициях из случайных партий, детерминизм при одном seed, выигрыш в 1 ход (обе стороны), стенка выбирается только при строго лучшем счёте, полнота кандидатов, жадный vs случайный (20 партий, лимит 300 полуходов, обе стороны: >= 18 побед), партия бот-бот завершается.
- Время на ход (10 партий greedy vs random, до 300 полуходов): GreedyBot среднее 3.5 мс, максимум 6.0 мс; RandomBot среднее 7.4 мс, максимум 11.9 мс (генерация всех стенок). Цель < 1 с выполнена с запасом.
- Жадный выиграл 10/10 в замере.

## Решения и почему
- Кандидаты только по пути соперника: быстро и без потери полноты для выбранной цели.
- `apply_move` внутри перебора повторно проверяет легальность (лишняя работа), для ботов фазы 2 некритично; для поиска (фаза 4/5) нужен быстрый apply без проверок.
- Жадный может зацикливаться (шаги туда-обратно) при равных счётах; в тестах против случайного не проявилось, лимит ходов нужен в арене/CLI.
