## Что хорошо
- Клиент присылает только список ходов. `engine.replay` проигрывает его через `parse_move` + `apply_move`, поэтому предусловие `is_wall_legal` выполняется (п. 2 «Первым шагом фазы 7»). Ход после победы отклоняется (`is_legal_move` на терминальной позиции даёт False), тест на это есть для обоих цветов.
- Легальность на фронте не дублируется. Подсветка, призрак стенки и «стенки закончились» опираются на `pos.legal` и `walls_left` с сервера.
- Безопасность: белый список статики, проверка Host/Origin (DNS rebinding, CSRF через simple request), лимит тела 64 КБ с 413 и закрытием соединения, `time` проверяется на тип. Серверные строки в `innerHTML` берутся только из `legal`/`top`, текст ошибок выводится через `textContent`.
- Отмена работает через `threading.Event`, проверка стоит в `evaluate` на каждом листе, задержка — доли секунды. Нелегальный запрос текущий анализ не отменяет (`replay` идёт до `start_job`), на это есть тест.
- Хорошие тесты: недоступность через не-loopback адрес, сканирование статики на внешние URL/WebSocket/beacon, подпроцесс останавливается по своему PID.

## Замечания

### major
1. **[major] `quoridor/analyzer/static/app.js:17-23` (и использование в 59-63, 77-84, 158):** клиент сам разбирает и форматирует нотацию сайта: `cellOf`, `wallOf` (`y = ряд − 2`, якорь = верхняя левая клетка), `fmtCell`, `fmtWall`, `fmtMove`, `moveOf`, а также `best.length === 3` / `last.length === 2` как признак стенки. Это прямое нарушение CLAUDE.md («Вся конвертация живёт в одном модуле `quoridor/notation.py`… Не размазывать знание о нотации по коду»). В 0045 это записано как сознательное решение, но исключение не согласовано. Вторую копию ничто не проверяет: JS не покрыт тестами. Если она разойдётся с `notation.py`, стенка будет нарисована в одном месте, а записана в партию под именем другой. Ошибка будет тихой: сервер проверит имя, а не картинку. Сейчас формулы совпадают с `notation.py` (`y = row0 − 1`), так что это риск, а не баг.
   → Сервер (через `notation.py`) отдаёт геометрию вместе с именами. `pawns` как `[c, r]`, `walls` как `{name, x, y, o}`, `legal` как `{name, k, c, r}` / `{name, k, x, y, o}`, `top[i]` с теми же полями. Клиент ищет ход по ключу геометрии (`"w:4:1:h"` → имя) и показывает `name`, сам ничего не форматирует. Буквы `a–i` на краю доски можно оставить: это подписи, не нотация. Добавить тест в `tests/analyzer/`: для каждого легального хода геометрия в ответе совпадает с `parse_move(name)`. Второй путь: пользователь явно вносит исключение в CLAUDE.md. Тогда нужен тест, который сверяет формулы JS с `notation.py` на всех 128 якорях.

### minor
1. **[minor] `quoridor/analyzer/server.py:138`:** при глубокой вложенности JSON (`[` × 60 000 в пределах 64 КБ) `json.loads` бросает `RecursionError`. Это не `ValueError`, поэтому ошибка не ловится: клиент получает обрыв без ответа, в stderr пишется трейс `Exception occurred during processing of request`. Проверено вручную. → Ловить `RecursionError` вместе с `ValueError` и отвечать 400, добавить тест.
2. **[minor] `quoridor/analyzer/static/app.js:108`:** `if (!res.ok) { toast(res.error); line.pop(); return refresh(); }`. Любая ошибка без номера хода, например 403 из-за другого Host/Origin (вероятно в фазе 9 с pywebview), приводит к бесконечному циклу запросов: пустой `line.pop()` ничего не меняет, а `refresh()` снова получает 403. → Откатывать ход только при `res.bad_move != null` (обрезать `line` до `bad_move − 1`), в остальных случаях показать ошибку и остановиться.
3. **[minor] `quoridor/analyzer/engine.py:158,168` + `app.js:159`:** `searcher.search(child, depth)` ищет от ребёнка на `depth` полуходов, значит от корня глубина `depth + 1`. В ответе и в UI («Глубина N») показывается на 1 меньше. В фазе 8 по глубине будут сравнивать оценки для разметки, поэтому смысл поля лучше зафиксировать сейчас. → Отдавать `done + 1` (или переименовать поле) и описать в докстринге `rank_moves`.
