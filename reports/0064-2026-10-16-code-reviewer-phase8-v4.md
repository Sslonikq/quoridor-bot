## Результаты ревью

### Корректность
- **PVS** (`_negamax`, строки 772–794; корень, 907–917). После первого хода идёт нулевое окно, а при `alpha < v < beta` (или при fail-high после редукции) ход пересчитывается полным окном. Fail-soft сохраняется, верхние границы корневых ходов (`scores[i] <= alpha`) корректны и используются в `search_top` как потолок. Логика `partial` при таймауте осталась корректной: улучшение засчитывается только после полного пересчёта. Тест `test_pvs_keeps_the_exact_score` (d2–d4, без LMR) подтверждает точность.
- **LMR** включается при индексе ≥ 3 и оставшейся глубине ≥ 3. Fail-high после редукции пересчитывается на полную глубину полным окном (сразу полным, без промежуточного нулевого окна: это дороже, но корректно). TT хранит записи по фактической глубине, так что смешения глубин нет. Как и любой LMR, это необоснованное отсечение: верхние границы альтернатив в `search_top` при LMR уже не строгие (см. minor 4).
- **`root_defense`** (`_defensive_walls`): перекрытие слева и справа, крест и сам квадрат угрозы. Набор блокирующих полный. Легальность проверяется через `wall_fits` и путь обоих игроков. Включается только при наличии стенок у обоих.
- **`delay_slack` / `_practical_loss`**: окно `(floor−1, floor)`, затем пересчёт с `alpha = floor−1`. Оценка получается точной для всех оставленных кандидатов. Ход, который не проигрывает, всегда выше проигрывающих. При `delay_slack=0` ветка не вызывается (v3 не меняется, подтверждено A/B).
- **Лимиты `_delay_loss`** (0059): с часами дедлайн выставляется всегда, а после дедлайна `_delay_loss` не запускается. Без часов работает лимит узлов (детерминирован). Проверка лимита встроена в существующую проверку раз в 64 узла. `_node_limit` сбрасывается в `finally`, `_reset` и `_free`.
- **`evaluate_v4`**: чистая функция, симметрична по стороне хода (тест `-v`). Темп учтён как в v3: `d_me <= d_op` против `d_op < d_me`, `e_me <= e_op` против `e_op < e_me`. Признак угрозы считается в `Searcher.evaluate`. Тест сверяет его с перебором 128 стенок, а при `threat=0` поведение совпадает с v3.
- **`bitpaths.shortest_layers`**: прямой BFS по фронтам, затем обратный проход по тем же маскам (рёбра неориентированные). Проверен тестом против определения «fwd == k и до цели d − k».
