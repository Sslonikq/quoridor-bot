## Задача
Фаза 9, шаг 1: подсказки анализатора можно считать MCTS (по умолчанию), v5 или v4; режимы времени «быстро 2 с / нормально 10 с / глубоко 30 с»; отмена и живой прогресс одинаково для всех ботов.

## Что сделано
- `engine.analyze(..., bot)` и `rank_moves(..., bot)`: белый список `BOTS = ("v4", "v5", "mcts")`, неизвестный бот это `ValueError`. v5 это тот же `Searcher` с `V5_SETTINGS`.
- MCTS (`_rank_mcts`): подкласс `MCTS` из `quoridor/mcts.py` (сам модуль не менялся), переопределён только `_simulate`: проверка отмены между симуляциями (`_Cancelled`, отклик за миллисекунды) и прогресс не чаще раза в 0,2 с. Настройки те же, что у `make_mcts` (`MCTS_SEARCHER`, `MCTS_OPTIONS`), сид 0, дерево на каждый запрос новое, весь бюджет в одном поиске.
  - Лучший ход и оценка: выбор бота (`MCTSResult.move/score`, оценка в шагах центи-шагах с учётом темпа, как у v4).
  - Топ-2/3: самые посещаемые другие ходы корня (по числу посещений, затем по значению); оценка из значения узла `atanh`, не выше оценки лучшего (иначе `exact = false`, в интерфейсе «≤»); доказанные выигрыш/проигрыш помечаются `mate`.
  - «Глубина» = длина главной линии (`res.depth`), в записи хода `visits`, в ответе `sims` и `bot`.
- Сервер: `POST /api/analyze` принимает `bot` (по умолчанию `engine.DEFAULT_BOT = "v4"`, чтобы не ломать старых клиентов; интерфейс шлёт свой, по умолчанию `mcts`). Неверное значение: HTTP 400 до отмены текущего расчёта. `/api/progress` теперь `{busy, depth, sims}`.
- Клиент: сегмент «MCTS / v5 / v4» рядом с режимами; выбор в `localStorage` (ключ `quoridor.analyzer.bot`, чтение/запись в try/catch, мусор и `constructor` дают MCTS). Смена бота пересчитывает позицию (как смена режима), повторный клик по тому же боту ничего не делает. Режимы: 2 / 10 / 30 с (ключи `fast/normal/deep` и ключ localStorage прежние, поэтому сохранённые значения мапятся без миграции; по умолчанию «нормально»).
- Живая строка: «MCTS, Глубоко: 12 из 30 с, главная линия 18, 15597 симуляций. Esc отменяет.» (для v4/v5 «глубина N»). Строка результата подписана ботом и режимом; в списке ходов у MCTS вместо глубины число посещений («1234 пос.»).
- Разбор партии не менялся: считается v4; подсказка из разбора подписана «Из разбора (v4)».

## Решения и почему
- `mcts.py` не трогал, а подклассировал: обращаюсь к закрытым `_root`, `_pv_len`, `_simulate`. Если ai-engineer переименует их, упадут тесты `test_engine.py` (см. «Следующий шаг»).
- Дерево не переиспользуется между запросами: проще и безопасно при отмене; цена — потеря накопленных симуляций при шаге вперёд.
- Умолчание API `v4`, умолчание UI `mcts`: тесты и сторонние клиенты не меняют поведение.

## Breaking changes
`engine.analyze` / `rank_moves` получили необязательный `bot`; `on_depth` может вызываться с двумя аргументами `(depth, sims)` (только MCTS). `/api/progress` содержит новое поле `sims`.

## Проблемы и открытые вопросы
- Оценки MCTS и v4 в разных шкалах по природе (MCTS: из среднего значения узла), поэтому график разбора (v4) и подсказка MCTS могут расходиться.
- Разбор партии по-прежнему на v4; бот для разбора не выбирается (по заданию).
