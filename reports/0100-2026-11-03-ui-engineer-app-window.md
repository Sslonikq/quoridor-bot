## Задача
Фаза 12: нативное окно pywebview поверх локального 127.0.0.1-сервера, закрытие окна завершает сервер, 📌 «поверх всех окон», компактный режим ~380 px, запоминание позиции/размера/режима/📌 в `~/.quoridor/analyzer.json`. Без pywebview всё должно работать в браузере.

## Что сделано
- `settings.py`: `SettingsStore` (load / get / update / save). Путь: параметр, иначе переменная `QUORIDOR_ANALYZER_CONFIG`, иначе `~/.quoridor/analyzer.json`. Битый или отсутствующий файл дают значения по умолчанию, поля проверяются по одному. Запись атомарная (mkstemp в том же каталоге + `os.replace`), каталог создаётся, ошибка диска не бросает исключение. Размеры хранятся отдельно для полного и компактного режима (`full_size`, `compact_size`).
- `window.py`: ленивый `load_webview()` (try/except любого исключения), `choose_mode()`, `clamp_to_screens()` (позиция за пределами всех экранов отбрасывается), `WindowApi` (js_api: `get_settings`, `set_on_top`, `set_compact` с `resize`; обработчики `moved`/`resized`; запись с задержкой 0.5 с и `flush` при закрытии), `run_native()` (модуль pywebview передаётся параметром, поэтому проверяется на моках).
- `__main__.py`: сервер идёт в потоке (daemon), GUI в главном потоке; закрытие окна возвращает из `run_native`, затем `server.shutdown()` и `server_close()` (по хэндлу, никаких убийств по имени). Нет pywebview или окно не открылось: предупреждение в stderr и браузер с `?nowin=1`; в интерфейсе появляется плашка. Новые флаги: `--browser` (принудительно браузер), `--config PATH`; `--no-browser` как раньше только сервер.
- Интерфейс: кнопки 📌 (скрыта без окна) и «◧ Компактно» (клавиша C) в шапке. Компактный режим (`body.compact`, колонка 380 px): доска, шкала оценки, статус, лучший ход + топ-3, кнопки ‹ › отмена переворот. Остальное (график, партия, загрузка, режимы, боты, подсказка вкл/выкл, « »), скрыто. В окне режим и размер переключает Python, в браузере только CSS, режим хранится в localStorage.
- `pyproject.toml`: `app = ["pywebview"]`.
- Совместимость: в `app.js` инициализация окна пропускается без DOM `window`/`body` (harness тестов клиента), Compact на «C» встроен в существующий единственный обработчик keydown (harness запоминает только последний).

## Решения и почему
- Python как источник правды для окна, JS только просит: правил на фронте нет, настройки не дублируются.
- Размеры раздельно по режимам: иначе переключение компактный/полный затирает размер другого режима.
- Запись с задержкой: события moved/resized идут потоком, при закрытии `flush`.
- Модуль pywebview внедряется параметром (тест на моках без установки пакета).
- Предупреждение «нет pywebview» выводится и при `python -m quoridor.analyzer` без флагов, и это штатный сценарий для тех, у кого пакета нет.

## Breaking changes
Нет. `--no-browser` ведёт себя как раньше (только сервер, Ctrl+C), добавлены флаги `--browser`, `--config`. Страница в браузере без `?nowin=1` ведёт себя как раньше, плюс кнопка «Компактно».

## Проблемы и открытые вопросы
- Не проверено на реальном pywebview: события `moved`/`resized` на разных бэкендах (Windows: EdgeChromium/WebView2), порядок `resize` после `set_compact` (возможно, `resized` перезапишет размер нового режима тем же значением, это безвредно), `window.on_top` как setter в установленной версии. Если API отличается, откат на браузер сработает только для исключений при старте.
- Позиция при `x=None` оставляет выбор системе.
- Если окно открывается в режиме без `pywebviewready` (медленный старт), через 600 мс интерфейс решит, что окна нет, и покажет браузерный вариант; маловероятно, но проверить.
