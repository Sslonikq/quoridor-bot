# 0109 · Зависание при 📌 и выбор времени/бота в компактном режиме

- **Дата:** 2026-11-03
- **Агент:** ui-engineer
- **Статус:** done (компоновку компактного режима глазами не видел: окно проверялось скриптом, без скриншота)

## Задача
1) Окно зависало («Не отвечает») после нажатия 📌 в реальном pywebview 6.2.1. 2) Добавить в компактный режим выбор времени анализа 2/10/30 с и бота.

## Что сделано
### Причина зависания (воспроизведена на реальном окне)
Пробный скрипт открыл настоящее окно, после `loaded` вызвал `pywebview.api.set_on_top(true)` из страницы. Вызов не вернулся, `faulthandler` показал поток js_api на строке `webview/platforms/winforms.py:1006`, в `set_on_top`: `i.TopMost = on_top`. Это не наш Lock и не `SettingsStore`: pywebview 6.2.1 (WinForms) ставит `Form.TopMost` прямо в вызывающем потоке, без `Invoke` (в отличие от `set_title`, `close`, `maximize`). `TopMost` пересоздаёт дескриптор окна, а из потока js_api это межпоточная операция с WebView2: UI-поток встаёт, окно «Не отвечает». Не зависит от идущего анализа (повторено после 14 с ожидания, когда MCTS закончил). Простое окно без WebView2 или вызов в другом контексте этого не показывает, поэтому проверка из голого потока «работает».
### Исправление
- `window.set_window_on_top(window, value)`: на WinForms ставит `TopMost` через `Control.Invoke` в UI-потоке (`BrowserView.instances[window.uid]`); если WinForms-бэкенда нет или API изменился, откат на `window.on_top = value`. `WindowApi.set_on_top` использует его.
- Проверено на реальном окне: 📌 вкл/выкл/вкл, клик по кнопке 📌 из страницы, `set_compact(true/false)` (resize через `SetWindowPos` не виснет, ошибок нет), окно отвечает (`evaluate_js("1+1")` = 2), закрытие через `destroy()`.
- (б) Блокировок в `SettingsStore`/`save_soon` нет: `_lock` у `WindowApi` держится только на время перезапуска таймера и не вызывает обратно; `SettingsStore._lock` не вложен. (а) js-вызов теперь возвращается сразу после `Invoke`.
- Заодно (nit ревью 0107): `lambda name=name: ...` заменён на `functools.partial(api.on_state, name)`.
- Найдено попутно: в настройки при запуске записывались координаты `-32000, -32000` (так Windows сообщает позицию свёрнутого/ещё не показанного окна). `on_moved` теперь игнорирует `x` или `y <= -30000`.
### Компактный режим
- Переключатели времени (`2 с / 10 с / 30 с`) и бота (`MCTS / v5 / v4`) больше не `full-only`, видны в одну-две строки; подписи режимов в компактном виде заменены на «2 с», «10 с», «30 с» (классы `lbl` скрываются, `kbd` показывается без рамки). Клиентская логика та же, что в полном режиме: выбор запоминается в localStorage, не связан с `analyzer.json` и не влияет на сохранение настроек окна.
- Значения по умолчанию подтверждены по коду: бот `mcts` (mcts3), время «Нормально» = 10 с (`loadMode`/`loadBot`).
- Высота компактного окна по умолчанию осталась 760: сжимать «вслепую» без скриншота не стал (если снизу пусто, уменьшить `compact_size` в `settings.py` или просто изменить размер окна, он запоминается).
